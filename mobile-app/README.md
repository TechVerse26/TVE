# Tech Verse Exam — Android app

A native-feeling Android app (React + TypeScript + Ionic + Capacitor) for the Tech Verse Exam platform.
It is **not** a web view of the website: every screen is designed for phones and tablets. It talks to the **same Firebase project, the same Firestore data, the same accounts and the same admin roles** as the website — an exam created in the app appears on the website and the other way round.

The website in the repository root is untouched (see *What changed outside `mobile-app/`* below).

## What is inside

| Area | What you get |
| --- | --- |
| Sign-in | Email + password only (no Google / phone in the app): sign up, sign in, forgot password, email verification mail, change password, sign out, persistent session. Google-only accounts get a safe path: *Forgot password* adds a password to the **same** Firebase account (same UID, same data). |
| Student | Home (live / next exam with countdown, resume banner, notices, recent results), Exams (search + filters), Exam detail, **Exam player**, Result + mistake review, Results history, Schedule, Leaderboard, My progress, Subjects, Academic programs, Notices, Profile + edit, Settings (theme, push, password), Help Center, FAQ, About, What's new, Privacy, Terms, Credits |
| Exam player | Rules screen, server-corrected countdown, answers lock when chosen (same rule as the website), question palette, autosave, resume after the app is closed, auto-submit at time-up, confirm-before-submit, Android Back guard, safe retry when offline |
| Admin (phones + tablets) | Dashboard, Exams (publish / draft / cancel / registration / delete + full exam & question editor), Students (search, roll number, deactivate), Notices, Push notifications, Results by exam, Admins & roles (Super Admin), Activity log |
| Native | Splash, launcher icon, status bar, Back button, safe areas, keyboard, push (FCM), tvexam:// links, network banner, light / dark theme |
| Tablet | Navigation rail, two-column layouts, side-by-side exam workspace |

The exam rules (schedule status, eligibility order, scoring, shuffling, saved-attempt deadline, result document, `userStats`) are **the website's own code**: the pure modules are copied byte-for-byte from `../js` into `src/shared/web` (`npm run sync:shared`, drift-checked by `npm test`), and the exam engine is a line-for-line port that is tested against the website's engine.

## Quick start

```bash
cd mobile-app
npm install
npm run dev        # opens the app in a desktop browser (Chrome) — real Firebase data
npm test           # app rules + parity with the website's exam engine
```

## Get an APK (pick one)

### A. GitHub Actions — recommended, nothing to install
1. Push the whole project to your GitHub repository.
2. (Optional but needed for push notifications) add the secret `GOOGLE_SERVICES_JSON` — see [ANDROID-FIREBASE.md](ANDROID-FIREBASE.md).
3. GitHub → **Actions** → **Android APK** → **Run workflow** → `debug` → wait ~10 minutes.
4. Open the finished run → **Artifacts** → download `TechVerseExam-APK` → unzip → install `TechVerseExam-1.0.0-debug.apk` on your phone (allow "install unknown apps").
5. Signed release APK: follow [docs/SIGNING.md](docs/SIGNING.md), then run the workflow with `release`, or push a tag such as `android-v1.0.0` — the APK is attached to a GitHub Release automatically.

### B. On your own computer (Android Studio)
Requirements: Node 20+, JDK 21, Android Studio (installs the Android SDK).
```bash
cd mobile-app
npm install
npm run android:debug      # builds the web app, creates android/ the first time, builds the APK → dist-apk/
npm run android:open       # optional: open android/ in Android Studio and press Run ▶
```
`android/` is generated by Capacitor on the first run (`cap add android`) and then adjusted by `scripts/android.mjs` (icons, permissions, version, signing hook). It is safe to re-run.

## Distribute the APK for free
* **GitHub Releases** (tag `android-v1.0.0`): a download link you can share. No Play Store needed.
* **Your website**: upload the APK to any static folder (for example `/downloads/TechVerseExam.apk` in the website repository) and link to it.
Students install it once; later versions install over it as long as they are signed with the **same key** (keep your keystore safe).

## What you must configure by hand
1. **Push notifications (optional):** register the Android app `com.techverse.exam` in Firebase and add `google-services.json` — [ANDROID-FIREBASE.md](ANDROID-FIREBASE.md). Without it the app works fully; only push is off.
2. **Redeploy the website's API** (Vercel) once so `server/push/engine.js` includes the new Android block — required for push to show while the app is closed.
3. **Firebase web API key restrictions:** if you restricted the key to your website domains in Google Cloud Console, also allow the app origin `https://localhost/*` (Credentials → the browser key → HTTP referrers). Otherwise sign-in fails inside the app.
4. **Release signing key (optional):** only for a signed release APK — [docs/SIGNING.md](docs/SIGNING.md).

## Free-tier facts (no card needed)
* **Firebase Spark:** Firestore 50 000 reads and 20 000 writes per day, FCM unlimited. The app caches aggressively (5–10 min), uses server-side counts for the admin dashboard and never keeps unlimited listeners.
* **GitHub Actions:** unlimited for public repositories; 2 000 minutes/month for private ones. A build takes roughly 8–12 minutes and only runs when you start it or push an `android-v*` tag — never on a schedule.
* **Cloud Functions are not available on Spark**, so (exactly like the website) exam timing is a server-clock-corrected deadline kept on the device, and the real gates are the Firestore rules. See *Security notes*.

## Security notes
* The app never bypasses `firestore.rules`; every admin write is authorised by the same rules and roles (`users/{uid}.isAdmin`, `adminRoles/{uid}`) as the website. Hiding a screen in the app is only a convenience.
* No service-account key, VAPID secret or password is in the app. The Firebase web config in `src/core/firebase.ts` is the website's public config.
* Saved exam attempts on the phone are signed (the website's integrity check) and removed after a successful save, on sign-out and on `allowBackup=false`.
* Admin push calls go to the website's `/api/push/*` with the signed-in admin's ID token; the server re-checks the role.

## Known limits (honest list)
* Not in the mobile admin yet (use the website admin): bulk question import, Email Center, homepage content editor, academic program management, subject/category editor, leaderboard publishing, analytics exports, site settings / maintenance switch.
* Exam duration cannot be enforced server-side on the free plan (same as the website).
* This delivery was built and checked in a sandbox **without internet**: see [docs/TESTING-REPORT.md](docs/TESTING-REPORT.md) for exactly what was and was not run (no `npm install`, no Vite production build, no Gradle APK build, no device test).
