# Push Notification — FCM দিয়ে শিক্ষার্থীদের ফোন ও কম্পিউটারে নোটিফিকেশন (ফ্রি · কার্ড ছাড়া)

Admin Panel → **Push Notification** (`admin.html#/push`; Super Admin ও Manager)। এটি আলাদা কোনো সাইট নয় — বিদ্যমান অ্যাডমিন প্যানেলের ভেতরেই চলে,
একই অ্যাডমিন লগইন ও রোল-সিস্টেম, একই ডিজাইন। কোনো নতুন ফ্রেমওয়ার্ক বা বিল্ড-স্টেপ নেই (Vanilla JS + Firebase-ই আছে)।

**যা করতে পারে:** শিরোনাম/বার্তা/ছবি/আইকন/গন্তব্য-পেজসহ নোটিফিকেশন লেখা · ফোন ও কম্পিউটারের প্রিভিউ · নিজের ডিভাইসে টেস্ট পাঠানো ·
সব সাবস্ক্রাইবড / একজন / কোনো পরীক্ষার / কোনো প্রোগ্রাম (section) / কোনো লেভেলের শিক্ষার্থীদের কাছে পাঠানো · এখনই বা ভবিষ্যৎ সময়ে পাঠানো ·
অপেক্ষমাণ নির্ধারিত নোটিফিকেশন বাতিল · ইতিহাস (সার্চ, ফিল্টার, পেজিনেশন) · অডিট লগ।

**মূল নিয়ম:** শুধু যে শিক্ষার্থী নিজে নোটিফিকেশন চালু করেছেন এবং ওই ধরনটি বন্ধ করেননি, তাঁর ডিভাইসেই যায়। "Accepted by FCM" মানে Google-এর পুশ-সার্ভিস
মেসেজ নিয়েছে — ফোনে দেখানোর নিশ্চয়তা নয় (FCM তা জানায় না), এবং কোথাও "Delivered" দাবি করা হয় না।

## ০. আগে সীমাবদ্ধতাটা জেনে নিন (আপনার শর্ত: কার্ড নয়, টাকা নয়, নিরাপত্তায় আপস নয়)

FCM-এ মেসেজ পাঠাতে **সার্ভারে চলা কোড** লাগে, যা Firebase-এর গোপন চাবি (service account) দিয়ে নিজেকে চিনিয়ে Google-কে বলে "এই ডিভাইসগুলোতে পাঠাও"।
সেই গোপন চাবি **কখনোই ব্রাউজারের JavaScript-এ রাখা যায় না** — রাখলে যে কেউ সাইট খুলে চাবি নিয়ে সবাইকে নোটিফিকেশন পাঠাতে পারবে।
Firebase-এর নিজের সার্ভার-কোড চালানোর জায়গা (Cloud Functions) **Blaze প্ল্যান (বিলিং অ্যাকাউন্ট/কার্ড) চায়** — তাই সেটা বাদ।

তাই সমাধান:

| দরকার | সাধারণ উপায় (কার্ড/Blaze লাগে) | এখানে যা করা হয়েছে (ফ্রি) |
|---|---|---|
| সার্ভার-কোড (চাবি রাখা, FCM HTTP v1 কল) | Firebase Cloud Functions | **Vercel Serverless Function** (`api/push/*`) — আপনার সাইট যেখানে আছে সেখানেই। Vercel-এর ফ্রি (Hobby) প্ল্যানে কার্ড লাগে না। চাবি শুধু Vercel Environment Variable-এ |
| ব্রাউজারে মেসেজ আনা | FCM Web SDK | একই (ফ্রি, Spark-এ সীমাহীন) |
| ডিভাইস-টোকেন ও ইতিহাস রাখা | Firestore | একই Firestore (Spark-এর ফ্রি কোটার ভেতরে) |
| ছবি রাখা | Firebase Storage (কার্ড লাগতে পারে) | ছোট করে Firestore-এ (সর্বোচ্চ ৭০০ KB, ৬০টি) অথবা কোনো https লিংক |
| সময়-ধরে পাঠানো (scheduling) | Cloud Scheduler (পেইড) | **ফ্রি বাইরের টাইমার** (cron-job.org বা GitHub Actions) যা প্রতি মিনিটে সার্ভারকে "ঘুম থেকে ওঠো" বলে — ধাপ ৮ |

Firebase প্রজেক্ট **Spark (Free)** প্ল্যানেই থাকে। কোনো Cloud Function, কোনো পেইড নোটিফিকেশন সার্ভিস, কোনো legacy FCM API ব্যবহার হয়নি।
নিরাপত্তা কমিয়ে ফ্রি করা হয়নি — যেটা নিরাপদে ফ্রি-তে সম্ভব না, সেটা সীমাবদ্ধতা হিসেবে ধাপ ৯-এ খোলাখুলি লেখা আছে।

## ১. চালু করার ধাপ (এই ক্রমে)

1. **কোড ডেপ্লয় করুন** (আপনি যেভাবে করেন — যেমন GitHub-এ আপলোড → Vercel নিজে ডেপ্লয় করে)। নতুন ফোল্ডার `api/`, `server/` আর ফাইল `package.json` সহ।
   Vercel `package.json` দেখে `firebase-admin` নিজেই ইনস্টল করবে। *(সাইট শুধু Firebase Hosting/GitHub Pages-এ থাকলে `api/` চলবে না — আপনার সাইট `tvexam.vercel.app`, তাই ঠিক আছে।)*
2. **Firebase Console** — ধাপ ২ (নিচে): API চালু আছে কিনা দেখুন, **VAPID কী** বানান, **service account key** নামান।
3. **Vercel → Project → Settings → Environment Variables** — ধাপ ৫-এর টেবিল অনুযায়ী `FIREBASE_SERVICE_ACCOUNT_B64` ও `CRON_SECRET` বসান। তারপর **Redeploy** (Environment Variable বদলালে নতুন ডেপ্লয় লাগে)।
4. **VAPID কী** `js/push/push-config.js`-এ বসান, ডেপ্লয় — ধাপ ৩।
5. **Admin Panel → Push Notification → Setup & Audit → Check again** — "Push server", "Firebase credentials" সবুজ হতে হবে; "Browser key (VAPID)" সবুজ হবে ধাপ ৪-এর পর।
6. **ফ্রি টাইমার** (cron-job.org) বসান — ধাপ ৮। (শুধু নির্ধারিত সময়ে পাঠাতে চাইলে লাগে; "এখনই পাঠান" এ ছাড়াও চলে।)
7. নিজের ফোন/ব্রাউজারে সাইট খুলে **Notifications পেজ → "নোটিফিকেশন চালু করুন"**, তারপর Admin → Push Notification → Send → **Send test**।

> VAPID কী না বসানো পর্যন্ত শিক্ষার্থীদের দিকের পুরো ফিচার **ঘুমিয়ে থাকে** — কোনো অতিরিক্ত ফাইল ডাউনলোড হয় না, কোনো কার্ড/বাটন দেখা যায় না।
> তাই কোড ডেপ্লয় করলেই সাইটের কিছু বদলায় না; আপনি ধাপগুলো শেষ করে কী বসালে তবেই ফিচার জেগে ওঠে।

## ২. Firebase Console কনফিগারেশন (প্রজেক্ট `tvsaccount`)

Firebase Console → প্রজেক্ট **tvsaccount** → ⚙ **Project settings**।

**(ক) Cloud Messaging ট্যাব**
- **Firebase Cloud Messaging API (V1)** → *Enabled* থাকতে হবে। *Disabled* দেখালে ⋮ মেনু → *Manage API in Google Cloud Console* → **Enable** (বিলিং লাগে না)।
- **Cloud Messaging API (Legacy)** → বন্ধ থাকুক। আমরা legacy API ব্যবহার করি না।
- একই পাতার নিচে **Web configuration → Web Push certificates → Generate key pair** → যে লম্বা লেখাটি আসে (সাধারণত `B…` দিয়ে শুরু, প্রায় ৮৭ অক্ষর) সেটাই **VAPID কী**। কপি করে রাখুন (ধাপ ৩)।

**(খ) Service accounts ট্যাব** → **Generate new private key** → একটি `.json` ফাইল নামবে। এটাই সার্ভারের গোপন চাবি।
- ⚠ কাউকে পাঠাবেন না, GitHub/চ্যাট/ছবিতে রাখবেন না, `js/` ফোল্ডারে রাখবেন না। শুধু Vercel Environment Variable-এ বসাবেন (ধাপ ৫)।
- `.gitignore`-এ এই ধরনের ফাইল আটকানো আছে, তবু ফাইলটা প্রজেক্ট-ফোল্ডারের বাইরে রাখাই ভালো।

**(গ) Firestore Rules — কোনো পরিবর্তন লাগে না।** নতুন কালেকশনগুলো (`pushDevices`, `pushNotifications`, `pushAudit`, `pushMeta`, `pushImages`, `pushImageData`) কোনো rule-এ নেই,
ফলে ব্রাউজার থেকে পড়া/লেখা **বন্ধ**; শুধু সার্ভার (Admin SDK) পারে। অডিট-লগের একটি কপি আপনার আগের `adminLogs`-এও যায় (সার্ভার লেখে), তাই Activity Logs-এও দেখা যায়।

**(ঘ) Web API key-তে restriction দিয়ে থাকলে** (Google Cloud Console → APIs & Services → Credentials): HTTP referrers-এ `https://tvexam.vercel.app/*` থাকতে হবে, আর "API restrictions" থাকলে
**Firebase Installations API**, **FCM Registration API** (এবং **Firebase Cloud Messaging API**) অনুমোদিত তালিকায় যোগ করুন। না করলে ব্রাউজারে টোকেন নেওয়া ব্যর্থ হয়।

## ৩. VAPID কী বসানো

ফাইল: **`js/push/push-config.js`**

```js
export const PUSH = {
  enabled: true,
  vapidKey: "এখানে Firebase থেকে কপি করা Key pair বসান",
  apiBase: "",
};
```

- VAPID কী **পাবলিক** (ব্রাউজারে থাকা নিরাপদ) — এটা service account-এর গোপন চাবি নয়।
- `apiBase: ""` = পুশ-API এই সাইটেই (`/api/push/…`)। সাইট অন্য কোথাও হোস্ট হলে তবেই বদলান (ফাইলের মন্তব্যে লেখা আছে)।
- `enabled: false` করলে কী না মুছেই পুরো ফিচার আবার বন্ধ হয়ে যায়।
- সেভ করে ডেপ্লয় করুন। Admin → Setup-এ "Browser key (VAPID)" সবুজ হবে।

## ৪. Service Worker নিবন্ধন (আপনাকে কিছু করতে হয় না)

- ফাইলটি **`firebase-messaging-sw.js`** — সাইটের root-এ (যেখানে `index.html`)। সরাবেন না, নাম বদলাবেন না।
- নিবন্ধন নিজে থেকে হয়: শিক্ষার্থী "চালু করুন" চাপলে সাইট `firebase-messaging-sw.js` কে আলাদা scope-এ (`./firebase-cloud-messaging-push-scope`) নিবন্ধন করে।
  scope আলাদা বলে সাইটের PWA `service-worker.js`-এর সাথে কোনো সংঘাত নেই — সেটি যেমন ছিল তেমনই আছে।
- Worker-এ কোনো গোপন তথ্য নেই: Firebase-এর পাবলিক Web config-ই শুধু URL-এ যায়।
- **ব্যাকগ্রাউন্ড** (সাইট বন্ধ/ব্রাউজার মিনিমাইজড): worker মেসেজ পেয়ে নিজে নোটিফিকেশন দেখায় — Tech Verse Exam-এর আইকন, ব্যাজ, শিরোনাম, বার্তা, ঐচ্ছিক ছবি সহ।
- **ফোরগ্রাউন্ড** (সাইট খোলা): worker চুপ থাকে; সাইট নিজেই পেজের ওপরে একটি ছোট ব্যানার দেখায় ("দেখুন" বাটনসহ) — দুইবার দেখানো হয় না।
- **ডুপ্লিকেট রোধ:** প্রতিটি নোটিফিকেশনের নিজস্ব id; একই id আবার এলে আগেরটির জায়গায় বসে (নতুন শব্দ ছাড়া)।
- **ক্লিক:** নোটিফিকেশনে ক্লিক করলে সাইটের **ভেতরের** নির্দিষ্ট পেজ খোলে (খোলা ট্যাব থাকলে সেটাতেই, নইলে নতুন ট্যাব)। সাইটের বাইরের কোনো ঠিকানা কখনো অনুসরণ করা হয় না —
  ঠিকানা বদলে Home হয়ে যায়। পরীক্ষা চলাকালীন ক্লিকেও শিক্ষার্থীকে পরীক্ষা থেকে সরানো হয় না।
- পরীক্ষা চলাকালীন কিছুই পেজের ওপরে আসে না; মেসেজ চুপচাপ (শব্দ ছাড়া) সিস্টেম-ট্রেতে অপেক্ষা করে।

## ৫. ব্যাকএন্ড নিরাপদে কনফিগার (Vercel Environment Variables)

Vercel → আপনার প্রজেক্ট → **Settings → Environment Variables → Add**। Environment: **Production** (চাইলে Preview-ও)। গোপন মানগুলোতে **Sensitive** বক্স টিক দিন।

| নাম | লাগবে? | কী বসাবেন |
|---|---|---|
| `FIREBASE_SERVICE_ACCOUNT_B64` | **হ্যাঁ** (এটি *অথবা* নিচেরটি) | ধাপ ২(খ)-এর `.json` ফাইলের base64 রূপ (নিচে দেখুন) |
| `FIREBASE_SERVICE_ACCOUNT` | বিকল্প | একই ফাইলের পুরো লেখা (JSON) — base64 না করতে চাইলে |
| `CRON_SECRET` | নির্ধারিত নোটিফিকেশনের জন্য | কমপক্ষে ৩২ অক্ষরের এলোমেলো লেখা (পাসওয়ার্ড-জেনারেটর বা `openssl rand -hex 32`) |
| `SITE_URL` | ঐচ্ছিক | `https://tvexam.vercel.app` (না দিলে Vercel-এর production ডোমেইন ধরা হয়) |
| `PUSH_ALLOWED_ORIGINS` | ঐচ্ছিক | সাইট অন্য ডোমেইনে থাকলে সেই ঠিকানা (কমা দিয়ে) |
| `PUSH_MAX_RECIPIENTS` | ঐচ্ছিক | একবারে সর্বোচ্চ ডিভাইস (ডিফল্ট ৫০০০) |
| `PUSH_ADMIN_PER_HOUR` / `PUSH_ADMIN_PER_DAY` | ঐচ্ছিক | প্রতি অ্যাডমিনের সীমা (ডিফল্ট ২০ / ৮০) |
| `PUSH_FUNCTION_BUDGET_MS` | ঐচ্ছিক | এক কলে সর্বোচ্চ সময় মিলিসেকেন্ডে (ডিফল্ট ৭৫০০; Vercel-এর ১০ সেকেন্ডের ভেতরে) |

**base64 বানানো:**
- Windows PowerShell: `[Convert]::ToBase64String([IO.File]::ReadAllBytes("C:\পথ\key.json")) | Set-Clipboard`
- Linux: `base64 -w0 key.json` · macOS: `base64 -i key.json | tr -d '\n'`
- কম্পিউটার ছাড়া (শুধু ফোন): base64 লাগবে না — ফাইলের পুরো লেখা `FIREBASE_SERVICE_ACCOUNT`-এ পেস্ট করলেও চলে।

**নিয়ম:**
- সেভ করার পর **Redeploy** করতে হয় — না করলে পুরনো ডেপ্লয় পুরনো মান নিয়েই চলে।
- এই মানগুলো কখনো `js/`-এর কোনো ফাইলে, রিপোতে বা চ্যাটে নয়।
- চাবি ফাঁস হয়েছে সন্দেহ হলে: Firebase Console → Project settings → Service accounts → *Manage service account permissions* → Keys → পুরনো key **Delete** → নতুন বানিয়ে Vercel-এ বদলান।
- `server/` ফোল্ডারের কোড Vercel স্ট্যাটিক ফাইল হিসেবে URL ধরে পড়া সম্ভব হতে পারে — তাতে **কোনো গোপন তথ্য নেই** (সব গোপন মান শুধু Environment Variable-এ), তাই ক্ষতি নেই।

**সার্ভার কীভাবে অ্যাডমিন চেনে:** প্রতিটি অনুরোধে ব্রাউজার Firebase-এর লগইন-টোকেন পাঠায়; সার্ভার সেটি Google-এর কাছে যাচাই করে, তারপর `users` ও `adminRoles` ডকুমেন্ট পড়ে দেখে
Super Admin/Manager কিনা — **প্রতিবার**। ব্রাউজারে ভুয়া কিছু বসালে বা কনসোল থেকে সরাসরি অনুরোধ পাঠালে ফল: লগইন নেই → 401, শিক্ষার্থী/Editor/Viewer → 403।

## ৬. শিক্ষার্থীর সাবস্ক্রিপশন (কীভাবে নোটিফিকেশন চালু হয়)

**কোথায়:** Notifications পেজের একদম ওপরে "পুশ নোটিফিকেশন" কার্ড — চালু/বন্ধ অবস্থা, ঘোষণা · পরীক্ষা · ফলাফল — তিনটি আলাদা সুইচ, আর "আপনার ডিভাইস" তালিকা (কোন ডিভাইসে চালু, এটি কোনটি)।
এটি সবসময় আছে, কখনো জোর করে কিছু চালু করে না।

**ব্যাখ্যা-কার্ড (সফট প্রম্পট):** ব্রাউজারের অনুমতির বার্তা সরাসরি দেখানো হয় না। আগে একটি ছোট কার্ডে বলা হয় নোটিফিকেশনে কী পাবেন, আর এটা যেকোনো সময় বন্ধ করা যায়।
তিনটি বাটন: **নোটিফিকেশন চালু করুন · এখন নয় · আর দেখাবেন না**। ব্রাউজারের আসল অনুমতি-ডায়ালগ খোলে **শুধু "চালু করুন" চাপার পর**।
কার্ডটি দেখা যায় যখন:
- শিক্ষার্থী লগইন করা, ডিভাইসটি পুশ সমর্থন করে, এবং এটি তাঁর **দ্বিতীয় বা পরবর্তী ভিজিট** (প্রথমবার নয়);
- তিনি Home / Exams / Schedule / Notifications পেজে আছেন;
- পরীক্ষা চলছে না, কোনো পপআপ খোলা নেই, অসমাপ্ত অ্যাটেম্পটের ব্যানার নেই;
- ব্রাউজারে সাইটটি ব্লক করা নেই।

**বারবার বিরক্ত নয়:** "এখন নয়" → ৭ দিন চুপ; দ্বিতীয়বার → ৩০ দিন; তৃতীয়বার থেকে আর আসে না। "আর দেখাবেন না" → চিরতরে (সেটিংস-কার্ড তবু থাকে)।

**ব্লক করা থাকলে:** কার্ড আসে না। Notifications পেজে লেখা থাকে কীভাবে ব্রাউজারের সাইট-সেটিংস থেকে খুলবেন; শিক্ষার্থী ফিরে এলে নিজে থেকে বুঝে নেয়।

**iPhone/iPad:** Safari-র সাধারণ ট্যাবে ওয়েব-পুশ কাজ করে না। Share → **Add to Home Screen** করে হোম-স্ক্রিন আইকন থেকে খুললে (iOS/iPadOS ১৬.৪ বা নতুন) তবে চালু করা যায়। কার্ড এটাই লিখে দেখায়, অকেজো বাটন দেখায় না।

**বন্ধ করা:** "এই ডিভাইসে বন্ধ করুন" → Firebase-এর টোকেন মুছে যায় (ডেলিভারি সঙ্গে সঙ্গে থামে) এবং সার্ভারে টোকেন মুছে ডিভাইসটি "বন্ধ" চিহ্নিত হয়। শিক্ষার্থীর অন্য ডিভাইস অক্ষত থাকে।
**লগআউট:** ওই ব্রাউজারের টোকেন মুছে যায় — পরের জন এই শিক্ষার্থীর নোটিফিকেশন পায় না।

**ডিভাইস ও টোকেন:** প্রতি শিক্ষার্থী-ব্রাউজার আলাদা রেকর্ড (সর্বোচ্চ ৮ ডিভাইস), আলাদা অবস্থা ও পছন্দ। ২৪ ঘণ্টার বেশি পুরনো হলে পরের ভিজিটে টোকেন নীরবে নবায়ন হয়
(শিক্ষার্থীর সুইচের পছন্দ বদলায় না)। ব্রাউজার টোকেন বদলালে সার্ভার পুরনোটির জায়গায় নতুনটি বসায়। FCM যে টোকেনকে মৃত বলে (ব্রাউজার আনইনস্টল/ডেটা মোছা), সেই ডিভাইস নিজে থেকে বন্ধ হয়ে যায়।

## ৭. অ্যাডমিন কীভাবে পাঠাবেন

Admin Panel → **Push Notification** (মেনুতে Communication অংশে)। তিনটি ট্যাব: **Send · History · Setup & Audit**।

**Send ট্যাব — ধাপে ধাপে**
1. **ধরন:** ঘোষণা / পরীক্ষা / ফলাফল (শিক্ষার্থীর সুইচের সাথে মেলে — যিনি ওই ধরন বন্ধ রেখেছেন তিনি পাবেন না)।
2. **শিরোনাম** (সর্বোচ্চ ৬৫ অক্ষর) ও **বার্তা** (সর্বোচ্চ ২৪০) লিখুন। **ছবি ও আইকন:** *Choose* চাপলে একটি ড্রয়ার খোলে — আগের সংরক্ষিত ছবির তালিকা, "Upload from this device", অথবা https লিংক। আপলোডের সময় ব্রাউজার ছবিটি ছোট করে JPEG বানায় (ছবির লোকেশন/EXIF তথ্য মুছে যায়) এবং সার্ভার আকার আবার যাচাই করে। আইকন ডিফল্ট Tech Verse Exam লোগো; চাইলে *Use default* দিয়ে ফেরানো যায়।
3. **খুলবে কোথায়:** সাইটের ভেতরের কোনো পেজ বাছুন (Home, Exams, Results, Schedule …)। সাইটের বাইরের ঠিকানা গ্রহণযোগ্য নয়।
4. **কারা পাবেন:** সব সাবস্ক্রাইবড শিক্ষার্থী · একজন শিক্ষার্থী (নাম/ইমেইলে খুঁজে) · কোনো পরীক্ষার শিক্ষার্থী (সবাই / এখনো জমা দেননি / জমা দিয়েছেন) · কোনো প্রোগ্রাম (section) · কোনো লেভেল।
   কতজন শিক্ষার্থীর কতটি ডিভাইসে যাবে — পাঠানোর আগেই দেখা যায়; কেউ ওই ধরন বন্ধ রাখলে আলাদা করে লেখা থাকে।
5. **কখন:** এখনই, অথবা ভবিষ্যতের তারিখ-সময় (সর্বোচ্চ ৩৬৬ দিন)।
6. **প্রিভিউ** (ফোন / কম্পিউটার) দেখুন → **Send test** (শুধু আপনার নিজের চালু-করা ডিভাইসে যায়; তাই আগে নিজের ব্রাউজারে চালু করা দরকার) → ঠিক থাকলে **Send**।
   পাঠানোর আগে নিশ্চিতকরণ আসে (কতটি ডিভাইসে যাবে সহ); "সব সাবস্ক্রাইবড শিক্ষার্থী"-কে **এখনই** পাঠালে নিশ্চিত করতে `SEND` লিখতে হয়। দুবার চাপলেও একটিই নোটিফিকেশন তৈরি হয়।
7. **ফলাফল-কার্ড:** কতটি ডিভাইসে লক্ষ্য ছিল, কতটিতে **FCM গ্রহণ করেছে (Accepted)**, কতটি প্রত্যাখ্যাত, কতটি মৃত ডিভাইস সরানো হয়েছে, কতটি বাদ পড়েছে। *এগুলো ফোনে দেখানোর প্রমাণ নয়* — পেজেই লেখা আছে।

**History ট্যাব:** সব নোটিফিকেশন (শিরোনাম, বার্তা, কারা, তৈরির সময়, নির্ধারিত সময়, অবস্থা, গ্রহণ/ব্যর্থ সংখ্যা, কে পাঠিয়েছেন)। সার্চ, অবস্থা-ফিল্টার, পেজিনেশন।
সারিতে ক্লিক করলে বিস্তারিত (ব্যর্থতার কারণ সহ); **অপেক্ষমাণ (scheduled) নোটিফিকেশন বাতিল** করা যায় (পাঠানো শুরু হয়ে গেলে আর যায় না); "আবার ব্যবহার করুন" লেখাটি Send-ফর্মে তুলে আনে।

**Setup & Audit ট্যাব:** "সব কিছু সংযুক্ত কিনা" চেকলিস্ট (সার্ভার, Firebase চাবি, VAPID, সাবস্ক্রাইবড ডিভাইস, টাইমার) + **Check again**; ফ্রি টাইমার বসানোর নির্দেশ ও **Run scheduler now**; বর্তমান সীমাগুলো;
**অডিট লগ** (কে কখন কী করলেন — পাঠানো, নির্ধারণ, টেস্ট, বাতিল, ছবি আপলোড/মোছা)।

**কে পারে:** শুধু **Super Admin** ও **Manager** (আপনার Email Center-এর মতোই)। Editor/Viewer-এর মেনুতেই আইটেমটি আসে না, আর সরাসরি অনুরোধ করলেও সার্ভার 403 দেয়।

## ৮. নির্ধারিত (scheduled) নোটিফিকেশন ও ফ্রি টাইমার

**সমস্যাটা:** Vercel-এর ফ্রি Hobby প্ল্যানের নিজস্ব cron দিনে একবারের বেশি চলে না। নির্ধারিত সময়ে নোটিফিকেশন ঠিক সময়ে যেতে হলে কাউকে প্রতি মিনিটে সার্ভারকে ডাক দিতে হবে।
পেইড scheduler নেওয়া হয়নি, তাই **ফ্রি বাইরের টাইমার** ব্যবহার হয়। দুটি উপায় (একটিই যথেষ্ট):

**উপায় ১ — cron-job.org (প্রস্তাবিত; প্রায় মিনিটে মিনিটে)**
1. cron-job.org-এ বিনামূল্যে অ্যাকাউন্ট খুলুন (লগইন করুন)।
2. **Create cronjob** → Title: `TVexam push scheduler` → **URL:** `https://tvexam.vercel.app/api/push/cron`
   (Setup & Audit ট্যাবে এই ঠিকানা কপি-বাটনসহ দেওয়া আছে)।
3. **Execution schedule:** *Every 1 minute*।
4. **Advanced** → **Headers** → নাম `Authorization`, মান `Bearer ` (শেষে একটি স্পেস) এবং তারপর আপনার `CRON_SECRET` — অর্থাৎ `Bearer আপনার-গোপন-লেখা`। Request method: GET (POST-ও চলে)।
5. Save → **Test run** → উত্তর `200`। কয়েক সেকেন্ড পর Setup & Audit-এ "Scheduler (free timer)" সবুজ হবে ও "Last call … minutes ago" দেখাবে।
*(cron-job.org-এর মেনুর নাম মাঝে মাঝে বদলায় — মূল কথা: ঠিকানা + `Authorization: Bearer …` হেডার + প্রতি মিনিটে।)*

**উপায় ২ — GitHub Actions (প্রায় ৫ মিনিট; দেরি হতে পারে)**
1. প্রজেক্ট GitHub-এ থাকলে `.github/workflows/push-scheduler.yml` আগে থেকেই আছে।
2. GitHub → Repository → Settings → Secrets and variables → Actions → **New repository secret**:
   `PUSH_CRON_URL` = `https://tvexam.vercel.app/api/push/cron` এবং `PUSH_CRON_SECRET` = আপনার `CRON_SECRET`।
3. Actions ট্যাবে workflow চালু করুন। (GitHub কয়েক মিনিট দেরি করতে পারে; ৬০ দিন কোনো কার্যকলাপ না থাকলে scheduled workflow থামিয়ে দেয়।)

**টাইমার না থাকলে?** তখনও নির্ধারিত নোটিফিকেশন যায়, তবে **শুধু যতক্ষণ কোনো অ্যাডমিন Push Notification পেজ খুলে রেখেছেন, ট্যাব সামনে আছে ও সাইন-ইন আছে**।
অ্যাডমিন প্যানেল ৩০ মিনিট নিষ্ক্রিয় থাকলে নিজে থেকে সাইন-আউট হয় (আপনার নিরাপত্তা-সেটিং — বদলানো হয়নি), তাই ভরসা করার মতো সময়-নির্ধারণের জন্য ফ্রি টাইমারই ঠিক পথ। Send ও Setup পেজেও এই কথা লেখা আছে।

কারা ডাক দিতে পারে: শুধু যে জানে `CRON_SECRET`। ভুল বা ফাঁকা সিক্রেটে সাড়া 401/403। এই কলটি কেবল "যা আগেই অ্যাডমিন নির্ধারণ করে রেখেছেন এবং সময় হয়েছে" তা পাঠায় — নিজে থেকে নতুন কিছু তৈরি করতে পারে না।

## ৯. ফ্রি-প্ল্যানের সীমাবদ্ধতা (সততার সাথে)

1. **"Accepted" ≠ ডেলিভারি।** FCM ডিভাইসে পৌঁছানোর রিপোর্ট দেয় না। তাই ইতিহাসে শুধু Accepted/Rejected/Removed গোনা হয়; কোথাও "Delivered" বা "Opened" লেখা নেই, এবং পাঠানো যাবে না।
2. **নির্ধারিত সময়ের নির্ভুলতা বাইরের টাইমারের ওপর।** cron-job.org ≈ ১ মিনিট; GitHub Actions ≈ ৫ মিনিট বা বেশি দেরি; কিছুই না থাকলে শুধু খোলা-অ্যাডমিন-পেজ (ধাপ ৮)।
3. **Vercel Hobby ফাংশনের সময়সীমা** (ডিফল্ট ≈ ১০ সেকেন্ড; কোড ৭.৫ সেকেন্ডে থামে ও পরের কলে বাকিটা পাঠায়)। বড় অডিয়েন্স কয়েকটি কলে ভাগ হয়; একটি নোটিফিকেশনে ডিফল্ট সর্বোচ্চ ৫০০০ ডিভাইস (বদলানো যায়)।
   Vercel-এর মাসিক ফ্রি কোটা ও শর্ত Vercel-এর সাইটে দেখে নিন; Hobby প্ল্যান সাধারণত ব্যক্তিগত/অ-বাণিজ্যিক ব্যবহারের জন্য — আপনার সাইটের ধরন অনুযায়ী তাদের শর্ত পড়ে নেবেন।
   (সার্ভার-অংশ ছোট — `api/` + `server/` — প্রয়োজনে অন্য ফ্রি/নিজস্ব হোস্টে নেওয়া যায়।)
4. **Firestore ফ্রি কোটা** (দিনে ৫০,০০০ read / ২০,০০০ write)। প্রতিটি পাঠানোয় ডিভাইস-তালিকা পড়া হয় (মোটামুটি প্রতি ডিভাইসে ১ read; ধরন ভেদে কম-বেশি) আর ইতিহাস/অডিটের জন্য অল্প write হয়।
   Send-ফর্মের "কতজন পাবে" গণনা `count()` ব্যবহার করে (সস্তা)। অপব্যবহার ঠেকাতে সীমা আছে: প্রতি অ্যাডমিন ঘণ্টায় ২০ / দিনে ৮০, মোট দিনে ৩০০, ধারাবাহিক দুই পাঠানোর মাঝে ৪ সেকেন্ড।
5. **ছবি:** Firebase Storage সাধারণত কার্ড/Blaze চায় — আপনার শর্ত রাখতে ছবি ছোট করে Firestore-এ রাখা হয় (≤ ৭০০ KB, সর্বোচ্চ ৬০টি) অথবা https লিংক। সব ব্রাউজার/ডিভাইস নোটিফিকেশনে ছবি দেখায় না
   (যেমন Safari/Firefox সাধারণত দেখায় না) — না দেখালেও লেখা ও আইকন ঠিকই আসে।
6. **iPhone/iPad:** শুধু Home Screen-এ যোগ করা অ্যাপে (iOS/iPadOS ১৬.৪+)।
7. **ডিভাইস অফলাইন থাকলে:** FCM-এ মেসেজের আয়ু ২৪ ঘণ্টা; তার আগে ফোন অনলাইনে না এলে মেসেজ বাদ যায়। ব্রাউজার/OS-এর Do Not Disturb, ব্যাটারি-সেভার, সাইট-নোটিফিকেশন বন্ধ রাখাও আটকাতে পারে — সার্ভার এগুলো জানতে পারে না।
8. **বাতিল:** শুধু অপেক্ষমাণ (scheduled) নোটিফিকেশন বাতিল হয়; পাঠানো শুরু হলে আর থামানো যায় না।
9. কোনো Cloud Function নেই — তাই Firebase Console-এর Functions ট্যাবে কিছু দেখবেন না; সার্ভার-লগ Vercel → Logs-এ। গোপন কোনো তথ্য লগে লেখা হয় না।

**যা চালানো হয়েছে:** পুশ-ইউনিট ১৪৭টি পাস · অ্যাডমিন ব্রাউজার-টেস্ট ১১০টি পাস · শিক্ষার্থী ব্রাউজার-টেস্ট ১৩০টি পাস · আপনার আগের সব ব্রাউজার-সেট আমার পরিবর্তনের আগে ও পরে হুবহু একই ফল দিয়েছে।

**যা এই পরিবেশে যাচাই করা সম্ভব হয়নি (আসল ডেপ্লয়ের পর আপনি একবার দেখে নেবেন):**
- আসল Firebase/FCM/Vercel — স্যান্ডবক্সে ইন্টারনেট নেই; তাই সার্ভারের **আসল কোড** চলেছে নকল Firestore/Auth/FCM-এর বিপরীতে। `firebase-admin` প্যাকেজটি ইনস্টল করা যায়নি (npm রেজিস্ট্রি ব্লক), Vercel ডেপ্লয়ে নিজে ইনস্টল হবে।
- ফোনের আসল সিস্টেম-নোটিফিকেশন দেখানো — হেডলেস ব্রাউজার তা দেখাতে পারে না; আসল worker-এর সিদ্ধান্ত (কী দেখাবে, কোন আইকন/ট্যাগ/গন্তব্য) আসল ব্রাউজার-রানটাইমে যাচাই হয়েছে, কিন্তু প্রথম **Send test** আপনাকেই করে দেখতে হবে।
- আপনার প্রজেক্টে আগে থেকেই ফেল করা টেস্ট (আমার পরিবর্তনে নয়): `pwa.test.mjs`-এ ২টি, `run_pwa.py`-তে ৬টি, `run_info.py`-তে ১৩টি — আসল প্রজেক্টে চালিয়ে একই ফল পাওয়া গেছে; ছোঁয়া হয়নি।

**ডেপ্লয়ের পর ৫ মিনিটের লাইভ-চেক:**
1. Admin → Push Notification → Setup & Audit → *Check again* → "Push server" ও "Firebase credentials" সবুজ।
2. নিজের ফোন/কম্পিউটারে Notifications পেজ → চালু করুন → অনুমতি দিন।
3. Send → ধরন "ঘোষণা", ছোট শিরোনাম/বার্তা → **Send test** → ডিভাইসে নোটিফিকেশন আসে; ক্লিকে সাইটের পেজ খোলে।
4. ব্রাউজার বন্ধ/মিনিমাইজ করে আবার Send test → ব্যাকগ্রাউন্ডে আসে।
5. ৩ মিনিট পরের সময়ে একটি নির্ধারিত নোটিফিকেশন বানিয়ে দেখুন টাইমার ঠিক সময়ে পাঠায় কিনা।
